# 自动下一集

状态：用户已确认整体设计；功能代码已实现，Android Debug 构建、23 个单元测试及 12 项 Android TV 模拟器场景通过。

## 实施前现状

- 详情页小窗与全屏共用播放器，已有手动上一集、下一集及选集操作。
- 播放器目前在播放结束时只更新状态，不自动切集。
- 应用进入后台会暂停播放；回到前台后等待用户手动继续。

## 已确认的行为

- 当前播放集播放到结尾、播放器报告播放结束后触发自动下一集；不根据剩余时长提前切集，不跳过片尾。
- 下一集仅按当前播放源的选集列表顺序确定；最后一集播放结束后停止，不自动换源查找后续集或循环播放。
- 自动下一集始终启用，不提供开关或用户偏好设置。
- 当前集结束后立即切换并播放下一集，不增加倒计时或取消提示；切集加载沿用现有加载提示。
- 详情页小窗与全屏均自动续播；自动切集后保持原有显示模式，不自动进入或退出全屏。
- 自动切集时保留已打开的菜单、选集面板或换源面板及遥控器焦点，只更新当前播放集标记；不套用手动切集时自动收起菜单和面板的行为。
- 手动快进到片尾或从接近结尾的播放记录续播后，剩余内容实际播放结束也触发自动下一集；尚未提交的定位目标不触发切集，定位操作本身不跨集。
- 若当前集结束事件与进入后台同时发生，允许自动切换并加载下一集，但必须保持暂停；后台加载完成后不得自动播放，返回前台后也等待用户手动播放。
- 应用进入后台时仍立即暂停；允许后台准备下一集不代表允许后台继续播放。
- 自动切到下一集后，地址解析或播放加载失败时停止并显示错误，等待用户手动重选该集或换源；不自动重试、不跳过失败集、不自动换源。
- 手动选集、上一集、下一集或换源优先于同时发生的自动切集；已过时的加载结果不得覆盖手动操作。每次播放结束只触发一次自动切集，避免重复回调导致连跳多集。
- 自动切集前先保存上一集的结束进度；下一集实际开始播放后及时写入下一集的起始进度，再沿用定时保存和离开时保存。加载失败或仅在后台加载且始终暂停时，不把播放记录提前更新为下一集。
- 播放记录保存失败不阻断切集或离开应用，沿用既有的尽力保存机制。

## 实施要点

- 在播放器报告播放结束时发起续播，并核对结束事件属于当前有效的播放请求且存在下一集。
- 自动切集与手动切集共用必要的加载流程，但分别处理菜单、面板、焦点和后台暂停状态：自动操作保留界面状态，且不能清除后台暂停约束。
- 为每次播放请求建立可核对的身份，防止重复结束事件、已取消的解析或换源结果覆盖较新的手动操作。
- 区分正在准备的资源与已实际开始播放、可写入观看进度的资源，防止定时保存或退出时保存误把后台预加载记为已观看。
- 播放开始后及时保存下一集起始进度，不受现有定时保存的等待时间影响。
- 保持现有手动选集、换源以及前后台暂停行为。

## 验收场景

- 小窗与全屏中，中间一集结束后均直接进入当前源列表的下一集，保持显示模式。
- 最后一集结束后停止，不循环、不换源。
- 菜单、选集面板或换源面板打开时结束，保留界面与遥控器焦点，更新当前播放集标记。
- 快进到片尾或从片尾续播后，实际播放结束触发一次续播；仅移动定位目标不触发切集。
- 结束与进入后台同时发生时，允许准备下一集；加载完成、返回前台均不自动播放，手动播放后开始观看。
- 下一集解析或播放加载失败时显示错误并停止，不自动重试、跳集或换源；可手动重选或换源。
- 自动切集与手动选集或换源重叠时，以手动选择为准；旧加载结果与重复结束通知不改变较新的选择。
- 下一集尚未播放或加载失败时，记录保留上一集结束进度；实际开始播放后及时更新为下一集，随即退出仍能继续该集。
- 原有暂停、定位、手动切集、逐层返回及后台暂停行为通过回归验证。

## 实现与验证（2026-10-03）

- `DetailPlaybackScreen.kt` 在播放器结束事件中发起当前源内的自动续播。自动操作保留菜单、面板、焦点和显示模式；小窗在解析下一集和缓冲时也显示加载提示。
