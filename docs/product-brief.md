# Android TV 应用设计摘要

此文档记录访谈中已确认的产品要求；设计完成前不开始应用实现。

## 已确认

- 应用是独立的原生 Android TV 播放端，以当前目录作为应用仓库。MoonTVPlus 源仓库放在 `vendor/MoonTVPlus` 作为只读 submodule；应用构建不依赖它，不在源仓库内实现应用。
- 用户填写自己部署的 MoonTVPlus 服务地址。
- 首次填写服务地址时，电视端键盘始终可用；同一局域网内可用手机扫码辅助输入地址。
- 手机扫码辅助页面首版仅用于输入服务地址，不作为日常遥控器；日常操作使用实体遥控器。
- 登录以手机扫码确认为主，电视端账号密码输入为备用。
- 若服务实例启用 Cloudflare Turnstile，电视端不直接提交账号密码；引导用户在手机网页完成人机验证与登录，再扫码确认电视登录。
- 首版最低支持 Android 6（API 23）。
- 首版面向 Android TV、Google TV 和可用方向键/确认键操作的普通 Android 电视盒子；手机和平板不是适配目标。
- 首版实现点播核心：电影、剧集、动漫、综艺的浏览、搜索、详情、播放，以及收藏和继续观看。
- 首版优先支持普通点播源；搜索结果中的私人影库、网盘等特殊来源暂不展示为可播放内容。
- 同一作品有多个普通点播源时，播放前自动测速；整个选源过程最多等待 5 秒，从已测得的可用源中选最快的。若无测速结果则按服务端顺序尝试，并允许用户手动换源。
- 首版内置播放器明确支持 HLS（m3u8）、MP4 和 FLV；其他容器与编码视设备能力尽力播放。
- 首版不提供弹幕。
- 首版支持视频流自带的字幕轨选择；不提供外挂字幕搜索、下载或上传。
- 首版仅支持在线播放，不提供影片下载后的离线播放。
- 应用在任何版本都不提供管理功能。
- 收藏与播放记录在服务实例支持服务端存储时与网页双向同步；若服务实例仅使用浏览器 localStorage，则保存在电视本机并告知用户无法跨设备同步。
- 本机收藏和播放记录按“服务地址 + 登录用户”隔离保留；切换后只显示当前身份的数据，用户可在设置中单独清除旧数据。
- 以 MoonTVPlus 服务版本 `225.1.0` 为首版验证基线；连接其他版本时检查必需接口，并对不兼容情况给出明确提示。
- 原生电视界面使用 Kotlin + Jetpack Compose for TV。
- 原生播放内核使用 AndroidX Media3 / ExoPlayer。
- 服务地址优先使用 HTTPS；用户明确选择后可连接 HTTP 服务，应用需说明登录凭据通过 HTTP 传输的风险。
- 首版通过 GitHub Releases 交付签名 APK，供用户手动安装。
- 首版在应用内检查更新、从应用的 GitHub Release 下载签名 APK，并调起 Android 系统安装界面；安装由用户在系统界面确认。
- 独立应用的 GitHub 仓库为 `git@github.com:sinpor/MoonTVPlus-native-tv.git`；应用内更新读取该仓库的 Releases。
- 应用仓库与 GitHub Releases 公开，电视无需 GitHub 登录即可检查和下载更新；签名材料不公开。
- 新原生应用与现有 WebView/GeckoView TV 壳并存，Android 应用 ID 固定为 `com.moontvplus.native.tv`。源码命名空间可使用不含 Java 关键字的名称。
- 发布版使用新建的独立签名密钥，开发者保留两个独立位置的加密备份并验证恢复；GitHub Actions 使用加密 Secrets 中的副本。
